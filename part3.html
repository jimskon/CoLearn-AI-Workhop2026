Architecture

Four Layers of AI Guidance

Every AI response a student sees is shaped by four layers stacked on top of each other. Layers 0–2 are context. Layer 3 is what you craft — it shapes the scaffolding for each individual question.

  • 0
    Platform Guidance

    Always on. Set by coLearn-AI, invisible to instructors. Core rules: nudge, never solve; match student language; one focused question at a time.

  • 1
    Class Guidance

    Set once per course by the instructor. Establishes the teaching contract: accept engagement, one nudge at a time, never list failures, stay in scope for this class.

  • 2
    Activity Guidance

    Set per activity. Teaching style, hint threshold, topic scope. Applies to every question in the activity.

  • 3
    Question-Level Guidance (your main job)

    Set per question: a feedback prompt (invisible to students) and a sample response (also hidden). Together they drive Accept, Nudge, and Flag for every submission to this question.

Key insight: You don’t write the AI’s replies. You write the criteria the AI uses to decide how to reply. One precise feedback prompt plus one or two sample responses is enough to control all three AI responses for a question.
Markup Language

The coLearn-AI Markup Language

Activities are defined in a LaTeX-inspired markup language. Each activity is a plain-text file parsed by the platform to build the student interface, configure the AI layers, and set up the epistemic trace.

Activity-Level Commands

CommandPurpose & Notes
\title{...}Activity title shown to students and in reports.
\name{...}Short internal name used in logs and exports.
\activitycontext{...}Layer 2: paragraph describing topic scope and teaching goals. Sent to AI with every evaluation request.
\aicodeguidance{...}Layer 2 supplement: specific rules for code evaluation (e.g., “require meaningful variable names”).
\studentlevel{...}Brief description of the student audience (e.g., “CS1 Python, week 6”). Calibrates AI language level.
\retries{n}How many times a group may attempt a flagged question before the platform moves them on. Typical: 2–3.

Section & Content Commands

CommandPurpose & Notes
\section{Title}{min}Starts a named section with a suggested time in minutes.
\text{...}Plain paragraph text shown to students.
\textbf{...}Bold inline text.
\begin{itemize} … \end{itemize}Bulleted list. Each item prefixed with \item.
\image{url}{alt}{width}Embeds an image. Width in pixels. Alt text is required.
\link{url}{text}Clickable hyperlink.
\questiongroup{Title} … \endquestiongroupGroups related questions under a shared heading. Optional.

Question Commands

Every question begins with \question{...} and ends with \endquestion. Inside, exactly one response-mode command specifies the question type.

CommandPurpose & Notes
Question wrapper
\question{text}Opens a question. The argument is the full question text shown to students.
\responsemode{answer}Marks this as an answer question. Required for AI evaluation.
\sampleresponses{...}One or more correct answers, hidden from students. Calibrates AI recognition of equivalent correct responses.
\feedbackprompt{...}Layer 3 instruction to the AI: one clear criterion for Accept vs. Nudge vs. Flag. Invisible to students.
\endquestionCloses the question block.
Response type — choose exactly one per question
\textresponse{n}Multi-line plain text box. n = number of visible rows.
\python … \endpythonPython code editor. Content between tags is the starter code.
\pythonturtle{WxH} … \endpythonturtlePython Turtle editor with embedded canvas. WxH = canvas size (e.g., 400x300).
\cpp … \endcppC++ code editor with syntax highlighting and compilation.
\table{Title} … \endtableTrace table. See sub-commands below.
\multiplechoice{} … \endmultiplechoiceMultiple choice. Options: \choice{...} and \correctchoice{...}.
Table sub-commands
\row Col1 & Col2 & …Defines a table row. First \row is the header.
\tresponseMarks a cell as student-fillable (text input). Use inside a \row.
Tip — Starter code: Content between \python/\endpython, \pythonturtle/\endpythonturtle, and \cpp/\endcpp becomes the pre-filled starter code in the editor. Leave blank for an empty editor; provide a skeleton to scaffold the task.

Flag if too vague.} \endquestion %% Section 2: Python range \section{Python — Rewriting a Loop}{12} \text{Below is a loop written with a literal list. Nudge if stop is 30 (misses 30).} \endquestion %% Section 3: Turtle \section{Python Turtle — Filled Square}{12} \question{Use a for loop to draw a filled square with side length 100. Nudge if off-by-one in range (e.g., including 5 or starting at 0).} \endquestion %% Section 6: Reflection \section{Reflection}{4} \question{Which question type gave your group the most productive discussion? Why?} \responsemode{answer} \multiplechoice{} \choice{Text explanation — forced us to articulate the concept} \choice{Python code — debugging range() arguments caused real discussion} \choice{Turtle — visible output made errors immediately obvious} \choice{C++ — syntax differences from Python sparked comparison} \choice{Trace table — stepping through by hand revealed what we didn't know} \endmultiplechoice \feedbackprompt{Accept any choice; ask the group to give one specific reason from their discussion that supports their choice.} \endquestion
Layer 3 Deep Dive

Writing Feedback Prompts & Sample Responses

The Feedback Prompt

The feedback prompt is the single most important authoring decision you make. It tells the AI the one criterion that determines Accept vs. Nudge vs. Flag. One criterion only — compound prompts lead to incoherent nudges.

The feedback prompt answers: “What must be true for this response to be accepted — and what one question should the AI ask if it is not?”

Three Worked Examples

Python CS1 — For Loops with range()

Question: Rewrite the loop below using range() so it prints the same values.
for value in [3, 6, 9, 12, 15, 18]: print(value, end=" ")
Feedback Prompt (invisible to students)

“Require a for loop with range() that generates 3, 6, 9, 12, 15, and 18. Stop must be ≥ 19. Ignore minor spacing differences.”

✓ range(3, 19, 3) → accept
💬 range(3, 18, 3) → nudge
⚠ literal list unchanged → flag
Sample Response (not shown to students)
for value in range(3, 19, 3): print(value, end=" ")

Python Turtle — Hexagon

Feedback Prompt

“Require a for loop that runs exactly 6 times, calls forward(80) and left(60) inside, and uses begin_fill/end_fill for blue. Accept any turtle variable name.”

Sample Response
t.fillcolor("blue") t.begin_fill() for _ in range(6): t.forward(80) t.left(60) t.end_fill()

C++ — Average of 10 integers

Feedback Prompt

“Require a for loop that iterates exactly 10 times, reads an integer inside the loop, accumulates a running sum, and divides by 10.0 or casts. Accept double or float for the total; push back on integer division.”

Sample Response
double total = 0; int val; for (int i = 0; i < 10; i++) { cin >> val; total += val; } cout << total / 10 << endl;
Authoring by Type

Authoring Tips by Question Type

A — Text Response (\textresponse{n})

Best for concept explanations, predictions, and reasoning. The AI reads the text and evaluates it against your feedback prompt.

  • Write as “explain” or “predict” — not “list” or “define.” Open-ended questions generate discussion.
  • Set n based on expected length — 3–4 rows for a sentence or two; 6–8 for a full explanation.
  • Feedback prompt: one concept — “Accept if the response mentions that range() excludes the stop value.” Not a rubric.
  • Sample response: student-level language — not a textbook definition.

B — Python Code Editor (\python … \endpython)

Students write or edit Python code in a syntax-highlighted editor. The AI evaluates code structure and logic against your feedback prompt.

  • Provide a skeleton, not a blank page — give imports, a starter comment, any boilerplate. The task should be 3–8 lines, not 30.
  • Feedback prompt: target structure, not style — “Require a for loop using range(), not a while loop.”
  • Two valid structures? Provide both as separate sample responses (blank line between).
  • Be explicit about equivalents you accept — “Accept range(5, 31, 5) or range(5, 30+1, 5).”

C — Python Turtle (\pythonturtle{WxH} … \endpythonturtle)

Students write code that draws on an embedded Turtle canvas. Output is immediately visible — great for loop-structure tasks.

  • Choose canvas size — 400x300 for most shapes; 500x400 for larger shapes. Width × Height.
  • Pre-fill the skeleton — import turtle, t = turtle.Turtle(), t.speed(3).
  • Feedback prompt: describe shape and structure — “Require a for loop that runs 4 times, forward(100), left(90).” The AI reads code; it does not run it.
  • Fill tasks: specify fill call order — many students put begin_fill() after the loop. Decide whether to accept and say so.

D — C++ Editor (\cpp … \endcpp)

Full C++ editor with syntax highlighting and compilation. AI evaluates structure, not just whether it compiles.

  • Pre-fill #include and main() — students focus on the loop, not boilerplate.
  • Name exact C++ constructs — “Require a for loop (not while), cout, endl or ’\n’.” C++ has more variation than Python; be precise.
  • Handle operator ambiguity — if both i++ and i+=1 are acceptable, say so in the prompt or provide both in sample responses.
  • Escape angle brackets — use &lt; and &gt; in markup; the authoring tool handles this automatically.

E — Trace Table (\table{Title} … \endtable)

Students fill in a structured table (typically an execution trace). Excellent for exposing off-by-one errors and loop invariant reasoning.

  • First row is the header — variable names as column headers. Keep them short.
  • Use \tresponse only for student-filled cells — fixed values (iteration numbers) are plain text.
  • Feedback prompt: specify all expected cell values — “Accept if number takes 1,2,3,4 and total accumulates as 1,3,6,10.”
  • Sample response: readable row-by-row list — “Iteration 1: i=0, total=0 → total=5.” Clearest form for the AI to match.
Authoring Principles

Rules for Good Layer 3 Guidance

One criterion per feedback prompt

Pick the single most important thing that distinguishes correct from incorrect. If you write “and” in the feedback prompt, split it into two questions.

Ask, don’t tell

Phrase the prompt so the AI asks about the missing piece rather than stating it. “Does range(3, 18, 3) include 18?” — not “The stop value is excluded.”

Sample responses show equivalence

Provide your most natural correct answer. Add a second sample if the question has two genuinely different valid forms.

Design for the trace you want

Work backwards: what reasoning should the epistemic trace reveal? Design the question and guidance so that path is visible in the submissions.

Step 3 — Enter into the Authoring Tool (15 min)

  1. Log in to colearn-ai.com and navigate to Instructor → New Activity.
  2. Set the title, student level, and activity context (Layer 2). 2–3 sentences on teaching goals and what the AI should emphasize.
  3. Add each question. Choose the question type, paste your question text, and enter starter code if using a code editor.
  4. Enter the feedback prompt (Layer 3 — students never see this).
  5. Enter the sample response (also hidden from students).
  6. Preview the activity to see the student view before testing.

Step 4 — Test Live (10 min)

One group member takes the student role and submits: (1) a clearly correct response → should get Accept; (2) a plausible but slightly wrong response → should get Nudge; (3) a response that misses the point entirely → should get Flag. Adjust and retest until the AI responds as intended.

Common authoring pitfalls
  • Feedback prompt too vague → AI accepts nearly anything. Fix: add one specific criterion.
  • Compound feedback prompt → AI gives incoherent nudges. Fix: one criterion only.
  • Only one sample response → AI rejects equivalent correct code. Fix: add a second sample.
  • No resolvable uncertainty → no productive struggle. Fix: ask for a prediction first.
  • Question too open-ended → AI can’t evaluate. Fix: narrow scope to one concrete concept.
